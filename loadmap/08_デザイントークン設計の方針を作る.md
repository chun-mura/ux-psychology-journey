## 概要

TypeScript と Figma Variables を使ったデザイントークンの設計方針を定め、コンポーネント実装（Issue #9）の土台を作る。「デザインの判断をコードに落とし込む」接続点となる。

---

## 学習順序

### ステップ1：既存のデザインシステムを1つ読む（45分）

ゼロから考えるより「優れた事例を読んでからトークン設計する」方が速い。

**[Tailwind CSS](https://tailwindcss.com/docs/colors) の設計を読む**（一番身近で学習しやすい）：

- [tailwindcss.com/docs/colors](https://tailwindcss.com/docs/colors) でカラースケールの命名規則を確認
- `gray-100〜900` という数値スケールが Primitive トークンにあたることを理解する

その後、3層構造の概念を理解する：

| レイヤー | 役割 | 例 |
| --- | --- | --- |
| Primitive | 生の値（変更しない基盤） | `blue-500: #3B82F6` |
| Semantic | 意味を持つ別名 | `color-primary: blue-500` |
| Component | コンポーネント固有 | `button-background: color-primary` |

「なぜ3層に分けるか」：Semantic を変えるだけでテーマ切り替えができるから。

### ステップ2：カラートークンを設計する（1時間）

まず Primitive カラーを決める（8〜10色 × 9段階のスケール）。

次に Semantic カラーに対応させる：

- `color-primary`：ブランドカラー、CTAに使う
- `color-text-default`：本文テキスト（コントラスト比 4.5:1 以上を確認）
- `color-error`：バリデーションエラー

[WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) でコントラスト比を確認しながら決める。

### ステップ3：タイポグラフィ・スペーシングトークンを定義する（30分）

タイポグラフィ：

- font-size は 12 / 14 / 16 / 20 / 24 / 32 / 40px（比率 1.25 か 1.333 ベース）
- font-weight は 400（Regular）/ 500（Medium）/ 600（SemiBold）/ 700（Bold）

スペーシング：

- 4px ベースの倍数系（4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px）
- コンポーネント内のパディングとレイアウトのギャップを同じスケールで管理する

### ステップ4：TypeScript でトークンファイルを作る（1時間）

```
tokens/
  color.ts
  typography.ts
  spacing.ts
  index.ts
```

型安全にすることで「存在しないトークンを使ったらコンパイルエラーになる」状態を作る。

### ステップ5：Figma Variables との対応表を作る（30分）

Figma のコレクション名とトークン名を1対1で対応させた表を作る。

[Tokens Studio](https://tokens.studio/) プラグインを使うと JSON から Figma Variables に自動同期できる。
