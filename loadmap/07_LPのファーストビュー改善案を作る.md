## 概要

実在するランディングページのファーストビューを分析し、行動心理・価値提案・視線誘導の観点で改善案を Figma で作成する。Issue #4（CTA事例）と Issue #3（STP）の知識を統合した最初の設計アウトプット。

---

## 学習順序

### ステップ1：分析対象のLPを選定する（15分）

以下の基準で選ぶ：

- **自分がユーザーとして体験がある**サービス（改善意図を説明しやすい）
- ファーストビューに改善の余地がある（完璧なLPは学習素材として使いにくい）
- 日本語LPの方が言語的ノイズが少ない

推奨：freee / マネーフォワード / Wantedly / Chatwork などの中規模SaaS。

選定後、「なぜこのLPを選んだか・何が気になるか」を1段落書いてから分析を始める。

### ステップ2：現状のファーストビューを分析する（1時間）

スクショをFigmaに貼り、以下の観点でコメントを書き込む（テキストラベルを使う）：

| 観点 | 確認内容 |
| --- | --- |
| **メッセージ**（5秒テスト） | 「誰のための何か」が5秒で伝わるか |
| **視線誘導** | Z パターン（横長画面）または F パターン（縦スクロール）に沿っているか |
| **CTA** | 配置・コピー・色は Issue #4 で学んだパターンと照らしてどうか |
| **社会的証明** | 利用社数・顧客ロゴ・レビューがあるか |
| **Fogg BM** | Motivation を高めているか、Ability を下げているか |

「良い点」と「改善点」を各3つ以上書く。

### ステップ3：改善案をFigmaで作る（2時間）

ヒーローエリア（見出し / サブコピー / CTA / ビジュアル / 社会的証明）を再設計する。

設計中は「なぜこうするか」を都度メモする：

- 見出しコピーを変えた → 「損失回避フレーミングに変更（"〜できない"→"〜を逃さない"）」
- CTAボタンの色を変えた → 「周囲とのコントラスト比を4.5:1以上に確保」
- 社会的証明を追加した → 「バンドワゴン効果で不安を低減」

### ステップ4：ビフォーアフター比較をまとめる（30分）

- 変更した要素と根拠の一覧表を作る
- 「この改善でCVRが上がると考える理由」を仮説として書く（数値根拠がなくても原則ベースでよい）
- 次に検証するとしたらどの指標を見るかを書く
