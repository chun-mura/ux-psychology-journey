# 行動設計とUI実践ガイド

Hook Model、Fogg Behavior Model、CTA、フォームUXの要点を1枚で参照できる簡潔版。

---

## 1. Fogg Behavior Model（B=MAP）

**行動（Behavior）= 動機（Motivation）× 能力（Ability）× プロンプト（Prompt）**

3要素が同時に揃った瞬間に、1回の行動が起きる。

| 要素 | 意味 | 設計のポイント |
| --- | --- | --- |
| **Motivation** | 行動したい意欲 | 快楽/苦痛、希望/恐怖、社会的受容/拒絶。感情に左右されやすく、直接コントロールは難しい |
| **Ability** | 行動のしやすさ（摩擦の少なさ） | 時間・お金・体力・**認知負荷**・社会的逸脱・非習慣性。**ここを下げるのが最も効率的** |
| **Prompt** | 行動を促すきっかけ | Spark（動機が低い人向け）/ Facilitator（能力不足の人向け）/ Signal（両方十分な人向け） |

**アクションライン**：Motivation × Ability が閾値を超えたときだけ行動が起きる。動機を上げるより、**Ability（摩擦除去）と Prompt（タイミング）**に集中するのが鉄則。

**用途**：新規登録、購入、LP、**CTA・フォームの摩擦解消**など「1回の行動」を起こしたい場面。指標はCVR。

## 2. Hook Model

**単発の行動を繰り返しの習慣に変える4ステップのループ。**

```
Trigger → Action → Variable Reward → Investment →（次のTrigger）
```

| ステップ | 内容 | 設計の狙い |
| --- | --- | --- |
| **Trigger** | 行動のきっかけ | 通知・広告（外部）→ 退屈・不安・孤独（内部）へ転換する |
| **Action** | 最小限の行動 | B=MAPに基づき、スクロール・1タップなど摩擦ゼロに近づける |
| **Variable Reward** | 可変的な報酬 | 予測不能さがドーパミンを刺激。Hunt（情報）/ Self（達成）/ Tribe（承認） |
| **Investment** | ユーザーの「仕事」 | データ・設定・実績の蓄積 → 損失回避 → 次のTriggerを強化 |

**用途**：リテンション、DAU、習慣化。指標は利用頻度・継続率。

**Fogg BMとの関係**：Hookの「Action」設計にB=MAPを使う。習慣ループを回すエンジンの滑らかさを、摩擦除去でチューニングする。

## 3. 良いCTA（Call to Action）

CTAは「Prompt」であり、Motivation と Ability を調整する最後の接点。

### 4つの設計軸

| 軸 | 良い例の条件 |
| --- | --- |
| **コピー** | 動詞で始める（「始める」「試す」）。ベネフィットか次の一歩が明確。「送信」より「無料で試す」 |
| **配置** | 視線の流れ（Z/Fパターン）の終点。ファーストビュー内、または判断材料の直後 |
| **色・視認性** | 背景とのコントラスト比を確保。周囲の要素と差別化 |
| **心理原則** | 損失回避・希少性・社会的証明・アンカリングを意図的に使う |

### よく使われる心理原則

- **損失回避**：「〜を逃す」「先行特典を確保する」
- **社会的証明**：「〇〇人が利用中」「エンジニア3万人が導入済み」
- **希少性**：「期間限定」「残り〇件」
- **リスク低減**：「クレカ不要」「14日間無料」→ Ability（心理的負担）を下げる

### 避けるべきパターン

- 曖昧なラベル（「こちら」「詳細」）
- 複数の主CTAが並列で競合する
- クリック後の結果が予測できない文言

## 4. 良いフォームUX

フォームは **Ability を最も下げやすい箇所**。B=MAPの実践で最も効果が出やすい。

### 基本原則

| 原則 | 理由 |
| --- | --- |
| ラベルはフィールドの**上**に置く | 視線移動・認知負荷を減らす |
| プレースホルダーでラベルを代用しない | 入力中に「何を入れるか」が消え、迷いが生じる |
| エラーは**リアルタイム**または離脱時に出す | 送信後に一括エラーは時間・認知コストが高い |
| 必須項目は「（必須）」と明示 | 送信失敗による二度手間を防ぐ |
| **1フォーム = 1目的** | 入力項目を最小限に。後回しにできる項目は後回し |

### 摩擦の分類（Fogg BM × フォーム）

| Abilityの種類 | フォーム上の摩擦例 | 改善の方向 |
| --- | --- | --- |
| 時間 | 入力項目が多い、確認画面が冗長 | 項目削減、自動入力、ステップ分割 |
| 認知 | ラベル不明、エラーが抽象的 | 具体的消息、入力例、インライン説明 |
| 習慣 | 電話番号の形式など慣習と異なる | マスク入力、自動フォーマット |

### アクセシビリティ（WCAG）

- **1.3.1** ラベルとフォーム要素を関連付ける
- **3.3.1** エラー内容を特定できるように伝える
- **3.3.2** 入力に必要な説明を提供する

## 5. 使い分け早見表

| 課題 | 使うフレーム | 主な施策 |
| --- | --- | --- |
| 登録・購入率を上げたい | Fogg BM | フォーム簡素化、CTA最適化、Prompt設計 |
| 継続利用・習慣化したい | Hook Model | 通知→内部Trigger、可変報酬、Investment設計 |
| ボタンを押してもらいたい | CTA設計 | コピー・配置・心理原則 |
| 入力を完了してもらいたい | フォームUX | 摩擦除去、アクセシビリティ |
